# 13 远程启停与低功耗待机改造方案

**状态**：已完成代码实现、全量宿主测试与固件构建，待完成实板功耗与启停循环验收
**适用对象**：传感器固件（v1.5 起）、网关固件（v1.5）；节点后续在 v1.6/v1.7 增加了静置自动休眠与 GPIO 唤醒，见本文 §4.1 补注
**明确不做**：节点侧模式 B / 边缘检测 / 漫游。
**目标读者**：实施者。本文给出协议定义、固件改动位置、硬件风险点及验收清单。

---

## 1. 目标与现状痛点

### 1.1 目标

1. 传感器节点上电后**默认不采集、不发 DATA**，进入**低功耗待机模式**（BMI323 Suspend + CH592F 真睡眠），仅周期唤醒发一次心跳 `STATUS` 并顺带接收网关 ACK 中的下行命令。
2. 通过主机协议远程发送启停命令，控制节点在「低功耗待机态」与「全速采集态（模式 A）」之间可靠切换。
3. 修复现有远程启停链路在状态同步、网关命令槽卡死、重启误执行、控制延迟方面的全部短板。

### 1.2 现有实现（v1.4）为什么不好用

| # | 现状位置 | 问题 |
|---|---|---|
| 1 | `firmware/sensor/app/status.c`（v1.4 现场，行号已漂移） | `STATUS` 未携带当前 `streaming` 状态，上位机只能靠本地猜测；重新连接或节点默认停采时会误报「样本已停更」，按钮状态不同步 |
| 2 | `firmware/sensor/app/main.c`、`idle.c`（v1.4 现场） | 上电写死 `streaming = 1`；停采后仍运行 20 ms `POLL_EVT` + 浅 Idle（约 4 mA），未进入真睡眠 |
| 3 | `firmware/gateway/app/gateway_core.c`（v1.4 现场） | 网关同节点有未确认命令时拒绝新命令（返回 BUSY=3），无过期/覆写机制，节点离线即卡死；节点重启（`boot_id` 变化）时未清旧待发命令 |
| 4 | `firmware/gateway/app/host_link.c`（v1.4 现场） | 网关新命令入队后未触发 `RF_Rx` 重挂，硬件仍挂着旧 ACK 缓冲，待机 2 s 心跳下控制延迟额外多等 1 个周期 |

## 2. 协议层改造（零长度开销，向后兼容）

不改变任何包长与字段偏移，旧版解析器仍可解帧，待机状态与温度需要按以下约定解释。

### 2.1 `STATUS.flags` 新增 bit 7：`PROTO_FLAG_PAUSED`

- `firmware/common/proto.h` 新增枚举常量：`PROTO_FLAG_PAUSED = 128`（`0x80`）。
- **语义**（仅 `STATUS` 包，偏移 2）：
  - `0`：节点处于**采集态**（`streaming == 1`）；
  - `1`：节点处于**待机/停采态**（`streaming == 0`）。
- 兼容性：v1.4 及以前固件 `STATUS.flags` bit 7 恒为 0，解析方仅可对支持该标志的固件使用此位判断待机状态。

### 2.2 `STATUS.bmi_temp_raw` 无效值约定

- `STATUS` 偏移 20 的 `i16 bmi_temp_raw`：当节点处于待机态（BMI323 Suspend，温度传感器关闭）时，固件固定填 **`0x8000`（`-32768`，即 BMI323 硬件原生无效码）**，不再轮询读取可能无效的温度寄存器。
- 解析方应将 `-32768` 视为温度不可用。

### 2.3 下行命令复用 `STREAM_CTRL (code = 0x02)`

- 继续使用现有主机帧 `HOST_QUEUE_DOWNLINK (0x82)` 与无线 ACK 命令区：`[node_id, cmd_id, 0x02, 0x01, 0|1]`（`0` = 停止采集并进待机，`1` = 开始采集）。
- 语义微调（网关侧）：`HOST_QUEUE_DOWNLINK` 对**同一 `node_id`** 允许新命令直接**覆写**尚未确认的旧命令槽，并返回 `CMD_RESP.result = 0`；仅当 8 个槽位被 8 个不同节点占满时才返回 `result = 3`（BUSY）。

## 3. 网关固件改造（v1.4 → v1.5）

> 当前链接基线中，网关发布版余 **448 B**、日志版余 **440 B**。修改缓存或 RF 路径后使用 `tools/check_firmware.py` 核对 RAM 入口与 2 KiB 栈。

### 3.1 同节点命令槽覆写（0 B RAM）

- 修改 `firmware/gateway/app/gateway_core.c` 中 `gw_queue_command()`：
  - 遍历 `core->commands[GW_COMMAND_SLOTS]`，若找到 `cmd->node_id == p[0]`：
    - 直接覆写该槽位的 `id`、`code`、`len`、`payload`，返回 `GW_COMMAND_OK (0)`。
  - 若无匹配槽且有空闲槽，写入空闲槽并返回 `GW_COMMAND_OK (0)`；否则返回 `GW_COMMAND_BUSY (3)`。

### 3.2 节点重启（`boot_id` 变化）同步清除旧命令（+24 B RAM）

- 在 `firmware/gateway/app/gateway_core.h` 的 `gw_core_t` 中增加紧凑的节点 boot 记录（8 槽，**实际占 26 B**：三个字段合计 24 B，另因 `uint16_t` 2 字节对齐在 `boot_ids` 前留 1 B 填充）：
  ```c
  uint8_t  boot_nodes[GW_CONFIRM_SLOTS];
  uint16_t boot_ids[GW_CONFIRM_SLOTS];
  uint8_t  boot_cursor;
  ```
- 修改 `gateway_core.c` 中 `update_confirmations()`：
  - 收到任意合法包（`DATA` / `STATUS` / `POLL`）时，在 `boot_nodes[]` 中查找 `node_id`：
    - 若找到且 `boot_ids[i] != boot`：判定节点已重启，更新 `boot_ids[i] = boot`，**清除 `confirmations[]` 中该节点全部条目**，同时**清除 `commands[]` 中 `cmd->node_id == node` 的全部待发命令**。
    - 若未找到：写入空闲槽或按 `boot_cursor` 轮替覆盖，同时沿用对 `confirmations[]` 的旧 boot 清理。
  - 效果：节点重启后绝不会继承上一个 boot 残留的停止/启动命令。

### 3.3 新命令入队后即时刷新硬件 ACK 缓冲（0 B RAM）

- `firmware/gateway/app/radio.c` 新增并导出：
  ```c
  GW_RAM void gateway_radio_refresh_ack(void) { rearm_requested = 1; }
  ```
- `firmware/gateway/app/host_link.c` 中处理 `HOST_QUEUE_DOWNLINK`：
  - `gw_queue_command()` 返回 `GW_COMMAND_OK` 后立即调用 `gateway_radio_refresh_ack()`。
- `radio.c` 中 `gateway_radio_poll()` 逻辑已支持 `rearm_requested == 1` 时按 625 µs 节流执行 `rearm(now)`：短暂停接收、写入含新命令的 ACK 双缓冲、重新 `RF_Rx`。
- 效果：主机下发命令后 < 1 ms 网关 ACK 即更新，节点下一次唤醒即可立即命中，控制延迟减半。

### 3.4 版本号

- `firmware/gateway/app/gateway_app.h`：`GW_FW_MINOR` 更新为 `5`（v1.5）。

## 4. 传感器节点固件改造（v1.4 → v1.5）

### 4.1 双态行为定义

> **v1.6 补注**：采集态新增第三种状态——静置 10 s 后自动休眠（`sensor_stats.motion_sleep`、`STATUS.mode = 2`）。
> 休眠期间停止心跳、`STATUS_EVT` 被丢弃，BMI323 以 50 Hz Any-motion 监测，PA4 高电平 GPIO 唤醒并保留 Flash 供电，
> 唤醒后在同一 `boot_id` 开新采样段。下表只描述待机/采集两态，自动休眠细节见 [节点说明](../firmware/sensor/README.md)。

| 维度 | 待机态（`streaming == 0`，默认） | 采集态（`streaming == 1`） |
|---|---|---|
| 上电默认 | `SENSOR_AUTO_START` 宏默认为 `0`（待机）；编译传 `SENSOR_AUTO_START=1` 可切回上电直采 | 收到 `STREAM_CTRL(1)` 切入 |
| BMI323 | Suspend：`ACC_CONF(0x20)=0`，清 FIFO `0x37=1`，关中断 `INT_MAP2(0x3B)=0`、`IO_INT_CTRL(0x38)=0` | 3200 Hz / ±16 g，INT1 水位中断开启 |
| PA4 中断 | 禁能（`PFIC_DisableIRQ(GPIO_A_IRQn)` 并清挂起标志） | 上升沿中断使能 |
| `POLL_EVT`（20 ms） | 队列排空后停止（`tmos_stop_task`） | 20 ms 周期运行 |
| `STATUS_EVT` 周期 | `SENSOR_STANDBY_STATUS_TICKS = 3200`（**2 s**，宏可配） | `1600`（**1 s**） |
| `STATUS` 内容 | `flags \|= PROTO_FLAG_PAUSED`，`bmi_temp_raw = 0x8000` | `flags` bit 7 = 0，实读温度 |
| 睡眠等级 | CH592F **真睡眠**（保留 RAM24K + RAM2K + EXTEND，RTC 唤醒） | 维持现有 v1.4 **浅 Idle**（`_WFE`） |
| 射频策略 | 心跳 `STATUS` 单次发送，收合法 ACK 即释放；无 ACK 最多重试 1 次后放弃该心跳继续睡 | 完整确认表 + 退避重传（不变） |
| PA6 指示引脚 | 休眠前拉低（`IDENTIFY` 闪烁期间保持浅 Idle 直到结束） | 每秒翻转（不变） |

### 4.2 上电初始化与启动握手

1. `board.c`：
   - 先将未使用的 PA/PB 引脚设为 `GPIO_ModeIN_PU`（**必须避开**外部 32.768 kHz 晶振引脚 PA10/PA11 及板载 SWD 调试引脚，防止晶振停振或锁调试口），消除悬空输入漏电。
   - SPI CSB（PA12）保持输出高电平；PA4 下拉输入。
2. `bmi323.c` 新增 `uint8_t bmi_suspend(void)`：
   - 软复位 `0x7E = 0xDEAF` → 延时 2 ms → 读 `CHIP_ID(0x00)` 核对 `0x43` → 写 `ACC_CONF(0x20) = 0`、`FIFO_CTRL(0x37) = 1`、`INT_MAP2(0x3B) = 0`、`IO_INT_CTRL(0x38) = 0` → 读回 `ERR_REG(0x01)` 记入 `sensor_stats.bmi_error`。
   - `sampler_init()` 在 `streaming == 0` 时调用 `bmi_suspend()`，不开启加速度计、不使能 PA4 中断。
3. 启动握手与防旧命令误执行（**关键竞态修复**）：
   - `rf_tx.c` 中 `apply_confirmation(ack)`：在 `startup_polls` 尚未清零前（前 2 次 `POLL` 握手期间），**跳过 `command_apply(ack)`**！
   - 原因：第 1 个 `POLL` 触发网关自动回传的是“收到该 `POLL` 之前”已装好的旧 ACK，其中可能残留上一 boot 的旧命令；网关在收到第 1 个 `POLL` 后清掉旧命令并重挂新 ACK，跳过启动 `POLL` 的命令解析可彻底杜绝跨 boot 误执行。
   - 上电默认待机时：
     - 完成 2 次 `POLL` 握手后，立即调用一次 `status_emit()` 上报首帧带 `PROTO_FLAG_PAUSED` 的 `STATUS`，让主机在首批 DATA 之前发现节点。
     - **网关未开机场景**：若 `POLL` 交换失败（无 ACK），待机态不要进入退避死循环；放弃本次尝试，将 `TX_EVT` 留待下一次 2 s `STATUS_EVT` 唤醒时再发起（单次心跳周期内最多试 1~2 次），确保无网关时同样维持微安级待机功耗。

### 4.3 状态切换细节（`command.c` / `sampler.c` / `main.c`）

1. **待机 → 采集（收到 `STREAM_CTRL(1)`）**：
   - 若当前已是 `streaming == 1`，仅更新 `cmd_ack`（幂等，不重启 BMI323，避免造成假分段）。
   - 若从 `0 → 1`：
     1. `sensor_stats.streaming = 1;`
     2. `sampler_reconfigure()`：初始化 BMI323、清空并重使能 PA4 上升沿中断。
     3. 启动 20 ms `POLL_EVT`，并将 `STATUS_EVT` 重置为 1 s 周期。
     4. 立即 `status_emit()`（`PROTO_FLAG_PAUSED = 0`，带最新 `cmd_ack`），同步回报采集状态和命令编号，随后 ~11 ms 第一包 DATA 到达。
2. **采集 → 待机（收到 `STREAM_CTRL(0)`）**：
   - 若当前已是 `streaming == 0`，仅更新 `cmd_ack` 并立即发一帧 `STATUS` 回显。
   - 若从 `1 → 0`：
     1. `sensor_stats.streaming = 0;`
     2. `sampler_reconfigure()`：先 `packer_flush()` 保存最后半包，再 `bmi_suspend()` 并禁用 PA4 中断。
     3. 记录 `standby_enter_rtc = sensor_rtc()`，立即 `status_emit()`（`PROTO_FLAG_PAUSED = 1`，带最新 `cmd_ack`）。
     4. **残余排空与超时兜底**：继续在浅 Idle 下发送 `sensor_ring` 中残余的 `DATA` 和这帧 `STATUS`（正常 < 50 ms 发完）；若停采时恰好射频断链超过 **1 s** 仍未排空，主动清空残余槽位（计入 `ring_drop`）并立刻进入待机真睡眠，防止失联卡在 4 mA 耗电。
     5. 排空完成后：停止 `POLL_EVT`，`GPIOA_ResetBits(GPIO_Pin_6)`，将 `STATUS_EVT` 切为 2 s 周期。

### 4.4 待机真睡眠（`idle.c`）

1. **进入条件**。节点处于待机，既无待发或进行中的射频交换，也无 `IDENTIFY`。TMOS `deadline` 须落在允许的待机窗口内，并为 `WAKE_UP_RTC_MAX_TIME` 留出 HSE 提前唤醒余量。回退到浅 Idle 时，单次等待不得超过 `IDLE_RTC_MAX`（约 20.6 ms）。
2. **设置 RTC**。调试版先排空 UART1，读取一次 MAC 后再屏蔽 PFIC 中断，重检进入条件。开启 `SEVONPEND` 并清空旧事件后，将闹钟设在 `deadline - WAKE_UP_RTC_MAX_TIME`（按 `RTC_MAX_COUNT` 回绕）。若 RTC 标志已置位或闹钟离当前时刻太近，保持看门狗并返回 `2`。
3. **睡眠和恢复**。此时才禁用看门狗复位，并用 `_WFE` 进入真睡眠。RTC 可以在 PFIC 中断屏蔽期间唤醒芯片，即使触发先于 `_WFE`，事件也会使该指令立即返回。睡眠保留 RAM2K、RAM24K、EXTEND 并使用 HSE 预启动。唤醒后检查 MAC，必要时通过 RTC 再留 10 ticks 给 Flash 恢复。随后恢复 HSE、60 MHz 主频、看门狗和中断，等待一个 RTC tick 后标记 RF 重配并返回 `0`。
4. **停采与配参**。停采先清 PA4 的 GPIO 中断使能，再屏蔽 PFIC 入口并清标志。待机真睡眠只保留 RTC 唤醒（采集静置后的自动休眠是另一条路径，用 PA4 GPIO 唤醒）。待机下 UART1 不实时轮询，建议切到采集态执行串口命令，或使用 `SENSOR_STANDBY_SLEEP=0` 的台架固件。关闭真睡眠或 Idle 的固件保留 `POLL_EVT` 喂狗。
5. **RAM 和校准**。移出节点不需要的 RF RX 路径，真睡眠使用独立 RAM 节。节点默认 24 槽（840 点，约 0.2625 s），当前 v1.7 发布版余 **696 B**、日志版余 **676 B**（v1.5 时为 808/788 B），两者均保留 2 KiB 栈和 6 KiB BLE 堆。节点关闭 SDK 的周期 BLE 校准和温度回调，避免额外待机调度和采集中的 Flash 校准。温变下的无线链路质量纳入接板观察。

## 5. 网页观测台启停操作

用网页观测台连接 v1.5 网关，等待心跳发现节点。选中节点并点击「恢复采集」后，网关将命令交给下次唤醒的节点。收到新 DATA 后页面确认恢复。点击「停止采集」可以让节点回到低功耗待机。

待机时只回传 STATUS，样本数可以是 0。网页现已识别无效温度码（显示「— °C」）和 `PAUSED` 标志（用于 `mode=2` 的「已休眠」提示）；
待机态（`mode=1`）仍未用于启停按钮同步，按钮状态依旧来自页面本地记录。操作说明见 [网页观测台](../web/README.md)。

## 6. 多节点扩展预留（本轮不实施群控 UI，但保证协议不返工）

1. 本轮网关的 `commands[8]` 与 `boot_nodes[8]` 均按 `node_id` 独立隔离，网页按节点和本次启动会话选择控制目标，逐个选中在线节点即可分别启停。
2. 后续阶段二若需「全部开始 / 全部停止」一键群控，提供两条平滑演进路径（不改现有帧结构）：
   - **优先（零固件改动）**：上位机遍历当前在线节点列表，逐个串行发送 `HOST_QUEUE_DOWNLINK`。对 8~30 个节点只需几十毫秒即可全部排入对应网关。
   - **可选（广播命令）**：后续扩展 `cmd_node_id = 255` 为广播命令，但广播无法单点 `cmd_ack` 清槽，需配合网关固定广播次数（如附带 N 秒后自动退出），因此阶段二也优先推荐逐节点下发。

## 7. 实施顺序与验收清单

### 7.1 推荐实施步骤

1. **Step 1（公共协议 + 网关 v1.5）**：改 `proto.h`、`gateway_core.h/.c`、`radio.c`、`host_link.c`、`gateway_app.h`；补充 `tests/gateway/test_gateway.c` 和 `test_host_link.c`；编译 `gateway` 与 `gateway-debug`，确认 `check_firmware.py` 通过且 RAM 未超。
2. **Step 2（节点 v1.5）**：改 `sensor.h`、`board.c`、`bmi323.h/.c`、`sampler.c`、`status.c`、`command.c`、`rf_tx.c`、`idle.c`、`main.c`；补充 `tests/sensor/test_command.c`、`test_idle.c`、`test_radio.c`、`test_sampler.c`；编译 `sensor` 与 `sensor-debug`，核查 map 与栈余量。
3. **Step 3（软件回归）**：运行 `make test` 并构建节点和网关固件。
4. **Step 4（实板联调与电流验收）**：依次烧录网关 v1.5 与节点 v1.5，逐项通过下方实板验收。

### 7.2 自动化测试必测用例

- **网关 C 测试**：
  - 同节点连续下发 `STOP` → `START`，后者成功覆写前者且返回 `GW_COMMAND_OK`；
  - 8 个不同节点占满后第 9 个节点返回 `GW_COMMAND_BUSY`；
  - 节点 `boot_id` 变化（即使通过 `POLL` 且确认表已被挤空）时，该节点旧待发命令被清除；
  - `HOST_QUEUE_DOWNLINK` 成功后触发 `gateway_radio_refresh_ack()`。
- **节点 C 测试**：
  - 上电默认 `streaming == 0`、`STATUS` 带 `PROTO_FLAG_PAUSED` 且 `bmi_temp_raw == 0x8000`；
  - 启动前 2 次 `POLL` 收到带旧命令的 ACK 时**不执行** `command_apply`；
  - 待机态心跳无 ACK 不陷入退避死循环；收到合法 ACK 即释放不发多余 POLL；
  - 采集 → 停采后立刻产生带 `PAUSED` 与 `cmd_ack` 的 `STATUS`，且断链超 1 s 自动清残余入睡；
  - 真睡眠进入条件门禁（仅在待机、环空、无 `IDENTIFY`、时间充足时进入；进睡前禁 WWDG、醒后重载并重开）。
