# 10 阶段一：单节点全量原始数据上传（当前实施范围）

**这是 codex 当前要实现的范围。** 01~03 是完整设计，本文件写明本阶段做哪些、跳过哪些，以及与 01~03 不同的决定；两者冲突时以本文件为准。

原 Python PC 工具已移除；当前实时观测上位机为 网页观测台（`web/index.html`）。本文中的完整主机持久化与重算功能保留为阶段一目标，当前固件入口与历史联调记录见 11，v1.5 远程启停与待机低功耗见 13。

目标：1 个节点用模式 A 随料架在 150 m 线体上运行，每个原始样本都可靠上传到 PC。
PC 连续保存数据，完成去重、排序、统一时间轴，所有缺口都有准确的样本区间和原因。功耗不在本阶段考虑。

## 1. 范围

本阶段做：
- 节点固件：BMI323 采集（INT1 中断驱动）、模式 A 发送、确认表、重传退避
- 网关固件：RF 接收、ACK 与确认表、USB CDC 转发、时间同步应答
- PC 端：串口接收、原始日志、重组、时间模型、Parquet 存储、简单波形查看器
- 台架测试、线体覆盖测试

本阶段不做：模式 B、休眠、太阳能、事件分类、位置推算（RSSI 照常记录，后续用）、多节点。
协议字段（node_id、确认表、漫游相关字段）按 02 完整实现，后续扩展时不用改协议。

## 3. 与 01~03 不同或新增的决定

### 3.1 时间基准：节点统一用 RTC

- 节点只用 RTC（外部 32.768 kHz 晶振），不用 SysTick。所有节点时间字段单位是 RTC 计数，`cfg.b7 = 1`。
- 工程预处理宏设 `CLK_OSC32K=0`。依据 `BLE/HAL/RTC.c`：该宏非 0 时开内部 LSI，为 0 时开外部晶振。
- 读 RTC 用 `R32_RTC_CNT_32K` 两次读取一致的方式（同 `RTC.c` 中 `SYS_GetClockValue`），回绕值以 SDK 中 `RTC_MAX_COUNT` 为准，PC 端按此展开。
- BMI323 时间换算成 RTC 计数：1 BMI tick = 39.0625 µs = 1.28 RTC tick，即 `rtc = bmi * 32 / 25`。
- 网关常开，用 SysTick 微秒（HSE 晶振），不变。

### 3.2 BMI323 INT1 → PA4，FIFO 水位中断

BMI323 寄存器（替换 01 §2 第 8 步）：

| 寄存器 | 值 | 说明 |
|---|---|---|
| FIFO_WATERMARK(0x35) | 140 | 35 帧 × 4 字，攒满正好够一个无线包 |
| INT_MAP2(0x3B) | 0x1000 | fifo_watermark_int → INT1（bit13:12 = 01） |
| INT_CONF(0x39) | 0x0000 | 非锁存：FIFO 低于水位时 INT1 自动拉低 |
| IO_INT_CTRL(0x38) | 0x0005 | INT1 输出使能、推挽、高有效 |

FIFO 满不再映射到中断。溢出判断靠 01 §3 的传感器时间连续性检查，以及 fill ≥ 1016 字。

MCU 侧：
- PA4 下拉输入，上升沿中断（`GPIOA_ITModeCfg(GPIO_Pin_4, GPIO_ITMode_RiseEdge)`，参考 SDK GPIO 中断用法），中断里只 `tmos_set_event(FIFO_EVT)`。
  该中断可能在 RF 等待期间触发，中断服务函数加 `__HIGH_CODE` 放 RAM（同 01 §6 的 RAM 运行要求）。
- `FIFO_EVT`：按 01 §3 的流程读取并解析，但要**把 FIFO 读空**（循环读整帧，直到不足 1 帧或已读 3 轮）。
  读完后若 PA4 仍为高电平，再置一次 `FIFO_EVT`，否则电平一直为高，不会再有上升沿。
- 兜底：保留 20 ms（32 tick）周期的轮询事件，防止丢沿后停采；FIFO 容量 80 ms，余量足够。
- 结果：约每 10.9 ms 一次中断，每次约 35 个新样本，正好一个无线包，延迟稳定。

### 3.3 网关与 PC 的连接：USB CDC

- 网关固件：RF 接收按 `BLE/RF_PHY` 的 RX 方向改写；USB 用 `USB/Device/COM` 的 CDC 实现；BLE 库与 USB 共存参考 `BLE/BLE_USB`。
- 主机帧格式沿用 03 §1.1（原来走 TCP 字节流，现在走 CDC 字节流，帧本身不变），类型名中的"服务器"即 PC。
- 主机接收层按字节流处理，串口为阶段一连接方式；远距离部署可使用 TCP 字节转发方案。

### 3.4 150 m 线体的覆盖

- USB 线最长约 5 m。远距离连接可选 USB 延长器（走网线），或在网关旁用小主机承担 USB CDC 与 TCP 字节流转发，主机帧保持原样。
- 步骤：先在线体中部放 1 个网关做覆盖测试（§4 S7）；有盲区再按 01 §6.1 加网关并启用漫游，频点 E1/E2/E3。
- 如果"带 LAN 的网关 PCB"上本身有以太网芯片，网关也可以直接走 LAN（03 §1 的 net_link），请告诉我芯片型号。

### 3.5 没有 Flash 时的缓存

节点 v1.5 按角色放置 RF RAM 代码，并使用独立的真睡眠入口。保留 6 KiB BLE 堆和 2 KiB 栈时，默认 **24 槽**，最多 840 个样本，在 3.2 kHz 下约 **0.2625 s**。STATUS 同占槽，实际可吸收的断链略短。网关为 8 槽接收队列，接近满时反压。四套固件的实测余量见 [接板验收文档](11_软件实现与接板验收.md)。
链路中断超过缓存时长时，超出部分以 RING_DROP 记录准确的样本区间。
能否做到全程连续，取决于覆盖测试结果。

V1 同时发生多类故障时不能唯一确定每段缺口原因，PC 会记录 `AMBIGUOUS`；
采集停顿超过 2 s 且 FIFO 满时，未知丢样量通过新段边界和 `UNKNOWN_SAMPLE_LOSS`
记录。这些边界尚不满足“所有故障均精确归因和计数”的总验收，详见 02 §7。

### 3.6 射频参数起点

1M PHY、0 dBm 起步。覆盖测试中依次试 +4.5 dBm、+9 dBm 和 2M PHY，按丢包率选择。

## 5. 本阶段总验收

- 完整性：线体上连续 24 h，覆盖范围内样本完整率 ≥ 99.9%；每个缺口都有原因和精确样本区间；输出零重复，按 sample_idx 严格有序。
- 时间：每个样本都有 UTC 时间戳。时间测试台：网关一个 GPIO 驱动电磁铁敲击节点，网关记录驱动时刻；
  PC 比较检出的冲击时刻与驱动时刻，去掉固定的机械延迟后误差 ≤ 2 ms，抖动 ≤ 0.5 ms。
- 可重算：删掉全部处理结果，从原始日志重算，结果一致。
