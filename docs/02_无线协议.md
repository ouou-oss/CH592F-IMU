# 02 无线协议

所有多字节字段小端序。结构体不要直接 `memcpy` 到包里（RISC-V 非对齐访问和填充风险），
用显式的 `put_u16/put_u32` 序列化函数；网页观测台与离线解码器按同样偏移显式解析。
`common/proto.h` 定义全部常量和偏移，固件、上位机与离线手册以它为准。

## 1. RF 参数（rfConfig_t）

| 参数 | 值 | 说明 |
|---|---|---|
| LLEMode | `LLE_MODE_AUTO \| LLE_MODE_PHY_1M \| LLE_MODE_EX_CHANNEL` | 硬件自动 ACK；用 Frequency 字段指定频点；白化默认开；可配置为 2M |
| Frequency | 节点用频点表中的当前频点，网关固定一个，单位 kHz | 见 §2 |
| accessAddress | 全网统一一个值（节点要在所有网关间漫游） | 不得用 0x55555555/0xAAAAAAAA；位翻转 ≤ 24 次，连续相同位 ≤ 6；与车间其他 2.4G 系统区分 |
| CRCInit | 全网统一，非默认值 | 进一步隔离其他系统 |
| RxMaxlen / TxMaxlen | 251 | |
| 发射功率 | 可配置，实验室 0 dBm，现场按覆盖测试调整 | rfConfig_t 无功率字段，codex 需确认用 `LL_SetTxPowerLevel()` 或 CONFIG 中 `BLE_TX_POWER` 生效 |
| 包类型匹配 | 节点 `RF_Tx(buf, len, 0xFF, 0xFF)`；网关 `RF_Rx(ack, len, 0xFF, 0xFF)` | 网关要接收所有节点，节点身份放在负载里 |

注意：LLEMode bit7（`LLE_MODE_NON_RSSI`）保持 0，回调 rxBuf[0] 为 RSSI，rxBuf[1] 为长度，负载从 rxBuf[2] 开始（见例程）。

## 2. 频点规划

- 避开 BLE 广播信道 2402 / 2426 / 2480 MHz。
- 国内 WiFi 常用 1/6/11 信道（2402~2422、2427~2447、2452~2472 MHz），也可能用 13 信道（2462~2482 MHz）。
- 频点角色：
  - E1/E2/E3：模式 B 网关，沿线按 E1-E2-E3-E1… 交替分配，同频网关之间至少隔 2 个站点。
  - S1/S2：模式 A 参考区专用接收端，每个模式 A 节点独占一个。
- 候选频点：2424、2448、2450、2474、2476、2478 MHz，相邻频点间隔 ≥ 2 MHz（1M PHY）/ ≥ 4 MHz（2M PHY）。**最终以现场扫频结果为准**。
- 频点表、access address、CRCInit 存在 DataFlash 配置里，可现场修改。

## 3. DATA 包（type = 0x1，传感器 → 网关）

包类型一览：0x1 DATA（模式 A 样本）、0x2 STATUS、0x3 SUMMARY（模式 B 每秒统计，见 05）、0x4 EVENT（模式 B 事件波形，见 05）、0x5 POLL、0x8 ACK。
下表中名字带 `_us` 的时间字段，实际单位由 `cfg.b7` 决定（模式 B 为 RTC 计数），字段名沿用 `_us` 只是为了简短。

包头 36 B + 样本 n × 6 B，1 ≤ n ≤ 35，总长 ≤ 246 B；零样本 DATA 非法。

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | u8 | ver_type | 高 4 位协议版本（=1），低 4 位类型（=1） |
| 1 | u8 | node_id | 1~254 |
| 2 | u8 | flags | b0 GAP，b1 FIFO_FULL，b2 CLIP，b3 NEW_SEGMENT，b4 RING_DROP，b5 LOW_BATT，b6 CFG_CHANGED，b7 PAUSED（仅 STATUS 使用：0 = 采集中，1 = 已停止/低功耗待机；v1.5 起） |
| 3 | u8 | cfg | b0~3 odr 码，b4~5 range 码，b6 bw，b7 时间单位（0 = µs，1 = RTC 32768 Hz 计数） |
| 4 | u16 | boot_id | 每次上电 +1 |
| 6 | u32 | seq | 本次上电内单调递增，DATA 与 STATUS 共用 |
| 10 | u32 | oldest_seq | 传感器缓存中最老未确认的 seq |
| 14 | u32 | first_sample_idx | 本包第一个样本的全局编号 |
| 18 | u8 | n_samples | |
| 19 | u8 | segment_id | 时间连续段编号 |
| 20 | u8 | attempt | 本包第几次发送，从 1 开始 |
| 21 | u8 | cmd_ack | 最后执行的下行命令 id |
| 22 | u32 | anchor_idx | 时间锚点样本编号（最近一次 FIFO 读取的最新帧） |
| 26 | u32 | anchor_us | 该样本的传感器本地时间（µs） |
| 30 | u32 | sync_txdone_us | 上一个被确认的发送的 TX 完成时刻（传感器本地 µs） |
| 34 | u8 | sync_seq_lo | 该发送的 seq 低 8 位 |
| 35 | u8 | sync_attempt | 该发送的 attempt |
| 36 | i16×3×n | samples | x, y, z 原始 LSB |

## 4. STATUS 包（type = 0x2，每 1 s 一个）

偏移 0~13 与 DATA 相同（ver_type、node_id、flags、cfg、boot_id、seq、oldest_seq）。

| 偏移 | 类型 | 字段 |
|---|---|---|
| 14 | u32 | sample_idx_now（下一待采样编号，已产生样本的右开界；尚无样本时为 0） |
| 18 | u16 | batt_mv |
| 20 | i16 | bmi_temp_raw（512 LSB/K，0 = 23 °C；0x8000 表示传感器休眠/温度无效，v1.5 起） |
| 22 | u32 | tx_ok |
| 26 | u32 | tx_retry |
| 30 | u32 | tx_backoff |
| 34 | u32 | ring_drop_pkts |
| 38 | u32 | ring_drop_samples |
| 42 | u32 | fifo_gap_samples |
| 46 | u16 | fifo_full_cnt |
| 48 | u8 | ring_max_used（槽数） |
| 49 | u8 | last_cmd_id |
| 50 | u16 | bmi_err_reg |
| 52 | i8 | ack_rssi_avg |
| 53 | u8 | fw_major |
| 54 | u8 | fw_minor |
| 55 | u8 | bmi_reinit_cnt |
| 56 | u8 | cur_gw_id（最近一次 ACK 的网关） |
| 57 | u8 | cur_ch_idx |
| 58 | u8 | mode（0 = B，1 = A，2 = 等待晃动唤醒，仅节点 v1.6 起） |
| 59 | u16 | solar_mv（无则 0） |
| 61 | u16 | roam_cnt（漫游次数） |

自动休眠前发送 `PAUSED=1, mode=2`。随后停止周期 `STATUS`，晃动唤醒后发送 `PAUSED=0, mode=1` 并恢复 DATA。普通停采继续发送 `PAUSED=1, mode=1` 心跳。v1.5 网关按原有格式转发。

## 5. POLL 包与 ACK

POLL（type = 0x5，20 B）：偏移 0~13 同 STATUS（seq 字段填 `next_seq`，不占用序号），
14 u32 sync_txdone_us，18 u8 sync_seq_lo，19 u8 sync_attempt。用途：换取新的确认表、漫游探测、给网关提供 RSSI 用于位置推算。

### 5.1 为什么需要确认表

RF 库 AUTO 模式下，ACK 内容是调用 `RF_Rx` 时传入的 txBuf，**在收到数据之前就已固定**，不能携带"刚收到的是谁的哪个 seq"。
多个节点共享信道时，可能出现：节点 X、Y 同时发送，网关只收到 Y，回的 ACK 却被 X、Y 都收到，X 误以为成功。
所以硬件 ACK 只表示链路层初步成功；网关每次重新挂接接收时，把最近收到的 (node_id, seq) 写进下一个 ACK，
节点在确认表里看到自己的 seq 才释放缓存（见 01 §5、§6）。

阶段一初始握手：网关按 `(node_id, boot_id)` 检测会话变化，变化时清除该节点旧确认项与旧待发命令（v1.5 起）；
POLL 只用于识别会话和交换 ACK，不加入确认表。节点启动先完成两次合法 POLL 交换，
握手期间忽略 ACK 命令区，再发送 STATUS/DATA，避免重启后把上一次 boot 残留的低 16 位确认项或旧命令误用于新会话。

codex 可以实测一个优化：在 `RX_MODE_RX_DATA` 回调里修改 ACK 缓冲，看能否在本次 ACK 中生效。
即使可以，也只作为加速手段，确认表机制保留。

### 5.2 ACK 负载（网关 → 节点，≤ 39 B）

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u8 | ver_type（类型 = 0x8） |
| 1 | u8 | gw_id |
| 2 | u8 | cmd_node_id（命令目标节点，0 = 无命令） |
| 3 | u8 | cmd_id |
| 4 | u8 | cmd_code |
| 5 | u8 | cmd_len（≤ 8） |
| 6 | u8[8] | cmd_payload |
| 14 | u8 | conf_n（≤ 8） |
| 15 | {u8 node_id, u16 seq_lo16} × conf_n | 确认表，最新的在前 |

下行命令（服务器 → 网关排队 → 附在 ACK 中，直到看到节点 `cmd_ack == cmd_id`）。
节点会漫游，服务器把命令发给该节点最近出现过的网关；网关有多个节点的待发命令时轮流附带。

| code | 命令 | 负载 |
|---|---|---|
| 0x01 | SET_ACC_CFG | odr 码、range 码、bw |
| 0x02 | STREAM_CTRL | 0 停止 / 1 开始 |
| 0x03 | SET_TX_POWER | 功率码 |
| 0x04 | SET_MODE | 0 = 模式 B，1 = 模式 A（附带持续分钟数，到时自动回 B） |
| 0x05 | REBOOT | — |
| 0x06 | IDENTIFY | LED 闪烁秒数 |
| 0x07 | SET_DETECT | 模式 B 检测参数（见 05） |

修改频点表（SET_CH_LIST）涉及全网切换和失败回退，放第二阶段。

当前阶段一网关仅排队 SET_ACC_CFG、STREAM_CTRL、SET_TX_POWER、IDENTIFY。
REBOOT 保留命令码但当前两端拒绝执行：尚未实现复位前的确认闭环，立即复位会使
网关反复重带同一命令，造成重启循环。需要复位时使用物理复位或节点 UART 配置后的 SAVE。
SET_MODE、SET_DETECT 与 SET_GW_CFG 当前返回不支持。

## 6. 交换时序与重传

```
节点: [DATA 约 2.05 ms @1M] --150µs--> 收 ACK --> TX_MODE_RX_DATA 回调
网关:  收 DATA → RX_MODE_RX_DATA 回调(抓时间戳、拷贝) → 自动发 ACK → RX_MODE_TX_FINISH → 写新确认表 → 重新 RF_Rx
```

- 网关在发完 ACK 到重新 `RF_Rx` 之间是"聋"的。节点成功后到下一次发送之间至少留 400 µs 间隔，
  codex 需用 GPIO + 逻辑分析仪实测网关的重新挂接延迟，再调整这个间隔。
- 重传、退避、漫游规则见 01 §6。未确认的旧包会在新包之后重发，所以 PC 端会看到乱序和重复。

## 7. 去重、排序、丢失判定

- 唯一键：`(node_id, boot_id, seq)`。重复包只保留第一份样本数据，但每一份副本都参与时间同步配对（attempt 不同，到达时间不同）。
- 排序：同一 boot 内按 seq；不同 boot 按首次收到的 PC 时间排序（boot_id 只有 16 位，可能回绕）。
- 节点侧不可重传：seq 缺失且小于已收到的最大 `oldest_seq`，节点已不再保留该包；PC 仍需考虑网关/主机队列中的迟到副本。
  否则视为"可能迟到"：模式 A 默认等 5 s；模式 B 节点可能在盲区里缓存很久，默认等 2 h。
  PC 不必等齐再写盘，先按到达写入，迟到数据到达后再按 seq 合并进对应时段。
- 样本缺口按 `sample_idx` 区间统计，并记录原因：GAP（FIFO 层丢样）、RING_DROP（缓存溢出丢包）、RADIO（seq 永久丢失）。
- `segment_id` 变化表示时间连续性中断，PC 对新段单独拟合时间。

`oldest_seq` 表示节点不再保留该包，不表示 PC 已经收到：网关已确认的数据仍可能在
USB/TCP 队列中。实时结果保留重排宽限；超过宽限的迟到包仍写原始日志，最终结果从
原始日志有序重算，不能仅凭 `oldest_seq` 丢弃有效迟到数据。

V1 的缺口原因来自包级标志与 STATUS 累计计数。FIFO、缓存和无线故障同时发生时，
这些信息不足以逐样本唯一归因；PC 保留精确样本区间，并把不能区分的原因记为
`AMBIGUOUS`。采集暂停超过 2 s 且 FIFO 满时，16 位传感器时间可能多次回绕；
固件清 FIFO、重启 IMU 并置 `GAP|NEW_SEGMENT|FIFO_FULL`，只累计已知样本进度，
PC 另记 `UNKNOWN_SAMPLE_LOSS`，不虚构未知丢样数。

## 8. 时间同步字段含义

- 锚点 `(anchor_idx, anchor_us)`：样本编号 → 传感器本地时间，PC 每段做线性拟合，得到实际 ODR 和偏移。
- 发送/接收配对：网关给每个收到的副本打 `rx_us`（网关本地 µs，RX_MODE_RX_DATA 回调入口）。
  节点在后续包（DATA/SUMMARY/EVENT/POLL 都带）里报告某次已收到硬件 ACK 的发送的 `(sync_seq_lo, sync_attempt, sync_txdone_us)`。
  两者都对应"数据包结束"这同一个物理时刻，配对后得到 节点时钟 → 网关时钟 的映射，每个网关单独一套。
- 网关时钟 → UTC：服务器通过 TCP 时间同步命令建立映射（见 03）。
- 节点在盲区期间产生的数据，时间用盲区前后两段同步结果插值（32.768 kHz 晶振约 ±20 ppm，10 分钟盲区插值后误差预期在毫秒级）。

阶段一仅报告成功收到硬件 ACK 的 DATA 发送作为同步配对，POLL/STATUS 不更新
最近发送配对；`sync_attempt=0` 表示还没有有效配对。POLL 不占 seq，STATUS 没有
attempt 字段，不能把它们与同序号 DATA 混用。AUTO 未产生 TX_FINISH 时采用
RF_Tx 前时刻，固定偏移需在台架上标定。
