## 已实现的阶段一链路

- 节点：7.5 MHz SPI0、BMI323 寄存器初始化与读回、PA4 水位中断、20 ms 兜底、FIFO 连续性/样本编号/锚点、分段恢复。
- 传输：独立 TX 缓冲、有限发送队列、硬件 ACK 与确认表分离、两次启动 POLL、重传/退避、STATUS。
- 网关：原生 CDC、ACK 双缓冲、合法包入队才确认、队满反压、USB 分片/断线完整重发、HELLO/TIME_RESP/GW_STATUS 和有限下行命令。

节点空闲降耗见[节点说明](../firmware/sensor/README.md)。模式 B、深睡眠/太阳能、
事件分类、位置推算和射频漫游不在当前实现中。
按需增加网关前，先做单网关覆盖测试。

## 容量按实际链接结果确定

厂家 `Link.ld` 只分配 **26 KiB RAM**。射频 AUTO 处理器及 USB 活动路径必须在 RAM，
不能只把应用忙等函数放 RAM。项目级 `firmware/Link.ld` 保持厂家 SDK 原件不变，
搬移当前 AUTO 路径，并通过链接断言预留 **2 KiB 栈**；链接后再检查关键入口地址。

- 节点默认 24 槽（`SENSOR_RING_SLOTS=24`），DATA 最多 840 点，在 3.2 kHz 下约 0.2625 s。STATUS 也占槽。
- 网关 8 物理槽：剩余不足 2 槽时不重挂接收，正常最多积压 7 包，约 76.6 ms；STATUS/POLL 会缩短这个时间。
- BLE 堆保持厂家配置 6 KiB，没有通过降低其运行前提来勉强链接。

以下为当前节点 **v1.7** / 网关 **v1.5** 的实测构建基线（GCC 8.2.0、RV32IMAC/ilp32，2026-11-25 `tools/check_firmware.py` 校验），单位均为 B；
RAM 列包含静态数据和搬入 RAM 的代码：

|---|---:|---:|---:|---:|
| sensor（24 槽） | 39120 | 23880 | 2048 | 696 |
| sensor-debug（24 槽） | 44632 | 23900 | 2048 | 676 |
| gateway | 29600 | 24128 | 2048 | 448 |

六套均已生成 ELF/HEX/BIN/MAP，并通过关键 RAM 入口、用户态 CSR 及栈边界检查。产物在 `firmware/build/`，历史 v1.3/v1.4 基线快照在 `build/firmware-memory-reviewfix.json`——这两个目录都不入库，克隆后需本地构建生成。
PA 构建相对原板多出 `BLE_PAControlInit` 调用与 24 B `pa_control` 配置结构，实测增量是 Flash +128 B、静态 RAM +32 B（含对齐与桩代码）；原板两种产物的数值未受影响。

链接检查验证节点 RAM 内的 TX 入口、网关 RAM 内的 RX 入口、6 KiB BLE 堆和 2 KiB 栈。修改宏后会自动重编并校验，节点至少保留 256 B 链接余量。`SENSOR_STANDBY_SLEEP=0` 的独立节点产物余 1,416 B，`SENSOR_IDLE=0` 的独立产物余 1,576 B。

## v1.5 烧录前回归

PA 板（`BOARD=pa`）另需：示波器确认 PA5(`TX_EN`)/PA4(`RX_EN`) 与 RF 活动不重叠、空闲与 120 s 校准窗口内两脚为低；
频谱仪确认 ACK 实际功率与 EIRP 符合限值；固定距离对比原板与 PA 板的上行 `rssi`，标定并复核 `PA_RSSI_OFFSET`。
网关只用硬件自动 ACK，厂商 `BLE_PAControlInit` 是否覆盖 AUTO 模式的应答发射必须在实板确认，见 [网关说明](../firmware/gateway/README.md)。

- 节点待机真睡眠仅使用 RTC 唤醒；采集静置后的自动休眠则用 PA4 高电平 GPIO 唤醒并保留 Flash 供电（v1.7）。浅 Idle 至多等待约 20.6 ms，禁用任一睡眠宏时保留 20 ms 轮询喂狗。实板应覆盖默认待机、长时间断链、启停循环和调试串口持续输出后的唤醒。
- 网关在 USB `CLEAR_FEATURE` 后清除相应端点状态，OUT 读取最多 64 B。下行帧解析上限为 88 B 负载（96 B 整帧），上行仍按公共协议上限处理。USB 序列号随 `APP_GW_ID` 生成。
- 网页对所选节点发送恢复或停止命令，收到开始后的新 DATA 才确认恢复。离线手册拒绝零样本 DATA。

## 已解决的跨端问题

1. **旧 boot 确认误释放**：确认表只有低 16 位 seq。网关识别 boot 变化并清旧条目，POLL 不进入确认表；节点启动先交换两次 POLL。
2. **同步配对别名**：只报告成功 DATA 的 `(seq_lo,attempt,txdone)`，POLL/STATUS 不更新配对；无配对时 attempt 为 0。
3. **原始重算缺 t1**：出站 TIME_REQ 也写入原始日志，记录 PC 发送时刻。
4. **oldest_seq 误判迟到**：它只表示节点已释放，网关队列仍可迟到。采集停止后自动从 raw 重算到 final。
5. **重复复位命令循环**：阶段一两端拒绝 REBOOT；主机得到不支持，而不是把排队成功误认为执行成功。
6. **运行期 Flash 取指**：节点完整启动/等待/关闭交换窗口在 RAM；网关 USB 描述符、功率码表及自有监听路径在 RAM。温漂校准先停收，再执行，之后恢复。
7. **网关复位混用时钟模型**：新启动/CDC 会话先发 HELLO，再发 RF_RX。PC 结合 TIME_RESP 计数倒退切换 epoch；GET_INFO 的 HELLO 不单独触发。
   同次读取且 PC 时间相同的旧帧、HELLO、新帧按原始记录顺序划界。缺少栅栏且归属有歧义时 UTC 保留 NULL。
8. **USB SETUP 错误拒绝与清中断顺序**：v1.2 不再用 SETUP 不更新的 RX_LEN 判断请求长度。
   旧 IN/OUT 与 SETUP 共存时，按手册先处理旧事务并清中断，再处理 SETUP 并再次清中断；保存新请求，避免旧 EP0 IN 重填缓冲覆盖它。
9. **节点时间快照早于 FIFO 新样本**：节点 v1.0 先读时间再读 FIFO，期间新增样本会被误算为早了约 2.56 s，随后虚增 8192 个丢样并产生假分段。
    节点 v1.1 在 FIFO burst 完成后读取传感器时间与 RTC 配对。回归能复现旧实现失败；刷写后 30 s 实测未再出现假缺样、分段或 UTC 倒退。

HELLO 现明确为 8 B `<BBBIB`。V1 既有线字段、偏移和 CRC 不变；新增说明用于消除未定义布局和语义歧义。
STATUS `sample_idx_now` 是已产生样本的右开界，不是最后一帧编号。

## 不能据当前软件宣称通过的指标

**混合故障精确归因**：V1 只有包级标志与累计计数。若缺失包同时跨越 FIFO 丢样和缓存丢包，
存在相同可见帧对应不同原因分布的情形。PC 保留精确区间与候选原因，记 `AMBIGUOUS`。
原总验收仍要求精确原因；需要后续明确扩展协议的损失报告，不能把歧义改名为已验收。

**极端采集停顿计数**：stop_on_full 保存的旧 FIFO 在长停顿时可能跨越多个 16 位传感器时间回绕。
超过 2 s 且满 FIFO 时节点清 FIFO、重启 IMU，新段置 `GAP|NEW_SEGMENT|FIFO_FULL`，
sample_idx 只保持已知样本进度。PC 记未知丢样量，不补造数量；不能据此保证所有故障的完整率。

**UTC 与吞吐**：仿真对比只能验证算法。AUTO TX_FINISH、固定 TX/RX 延迟、USB/NTP 非对称延迟、
1 h 无 GAP、91 包/s、0.2 s 实际断链零损失及 24 h 完整率，均需目标板实测。

**网关掉电**：已由网关确认、尚未交付 PC 的 RAM 包会丢失；节点不会再次保留这些包。
因此短 RF 断链与网关断电必须分开测试，当前机制不能保证 04 中“网关断电 0.2 s 零丢样”的目标。

## 接板按这个顺序验收

| 步骤 | 操作 | 通过依据 |
|---|---|---|
| 1 采集 | 节点日志版，核对 PA4、SPI 和外部 32K，连续采集 1 h | CHIP_ID=0x43，ERR_REG=0，静止 Z≈2048 LSB；样本率 3200 Hz±1.7%，水位中断约91/s，零采集 GAP |
| 2 USB | 使用支持 DTR 的 CDC 收帧工具，按 03 文档的主机协议检查 | CDC 枚举/反复打开正常，主机 CRC 正确，原始日志增长，TIME_REQ/RESP 有往返 |
| 3 RF | 近距离连续发送，观察 PA5/PA6 测试点和统计 | 稳定约91 DATA包/s；测重新挂接延迟；确认AUTO TX_FINISH与固定偏移 |
| 4 故障 | 0.2s/2s RF断链、网关掉电分别测；FIFO暂停150ms；PC暂停读取/USB重连 | 短 RF 断链在实测缓存内无损；长断链及掉电记录实际丢失区间；无误确认/重复输出，恢复不死锁；掉电零丢目标单独判定 |
| 5 时间 | 网关GPIO驱动敲击，标定机械与收发固定延迟 | 去固定延迟后误差≤2ms、抖动≤0.5ms；三级残差符合03/04文档目标，零未校准样本 |
| 6 覆盖 | 料架在线体跑≥10圈 | 保存每秒RSSI/丢失/缺口；根据盲区决定网关布局和是否启用后续漫游 |
