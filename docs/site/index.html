节点上电后做什么？

  1. 建立身份和时钟

    读取配置，boot_id 每次上电递增；RTC 使用外部 32.768 kHz 晶振，cfg.b7 = 1。先完成两次 POLL 握手。

  2. 待机或初始化 BMI323

    v1.5 默认上电待机（BMI323 Suspend + LowPower_Sleep，2 s 心跳带 PAUSED 标志）；收到 STREAM_CTRL(1) 后切到 SPI、检查 CHIP_ID = 0x43 并使能 3.2 kHz、±16 g、800 Hz 带宽。

  3. 水位触发并读空 FIFO

    35 帧达到 140 字水位，经 INT1 → PA4 触发。约每 10.9 ms 读一次；20 ms 轮询兜底，避免丢沿后停采。

  4. 持续封包和发送

    每包样本必须连续；GAP、段变化、配置变化或最老样本等待 100 ms 时提前封包。采集态每秒一包 STATUS，与 DATA 共用 seq。

02 / TWO LINKS

两段链路，两层协议

NODE ↔ GATEWAY

2.4G 私有无线

使用 WCH RF_PHY 自动 ACK，非 BLE GATT。阶段一从 1M PHY、0 dBm 起步，按现场丢包率再试 +4.5 / +9 dBm 和 2M。

  • 无线负载上限 251 B，DATA 最大 246 B。
  • 节点和网关的频点、access address、CRCInit、PHY 必须匹配。
  • 包类型：DATA、STATUS、POLL、ACK；SUMMARY / EVENT 留给模式 B。
  • 候选频点为 2424 / 2448 / 2450 / 2474 / 2476 / 2478 MHz，须现场扫频确定。
GATEWAY ↔ PC

USB CDC 字节流

网关把无线包包进 RF_RX 主机帧，增加 gw_id、rx_us 和 RSSI。CDC 或局域网 TCP 转发，主机帧完全相同。

  • USB / TCP 的一次读取不等于一帧，需自行拆帧。
  • PC 按 A5 5A 找帧头，用 len 确定边界，再验 CRC。
  • frame_seq 用来发现网关内部丢帧，不代替无线 seq。
  • 远端网关可由小主机进行串口 ⇄ TCP 双向原样转发，不改时间戳。
150 m 线体怎么接？

先把一个网关放在线体中部测试。USB 线约 5 m，远端用网关旁的小主机转到车间局域网，或用 USB 延长器。发现盲区后再增加网关、分配 E1/E2/E3 并启用漫游；阶段一不预先固定网关数量。

下行命令如何到达节点？

PC 发 QUEUE_DOWNLINK → 网关排队 → 命令附在 ACK 中 → 节点执行并回显 cmd_ack。网关持续附带，直到看到对应命令编号；节点根据 cmd_id 避免重复执行。节点漫游时，PC 向该节点最近出现过的网关发命令。

code命令负载

当前仅支持加速度配置、开始/停止、发射功率与 IDENTIFY。REBOOT 因可能重复重启而拒绝；模式切换、检测参数和频点表留待后续阶段。

06 / INTEGRITY & TIME

收到 ACK，不等于可以丢掉缓存

RF 自动 ACK 的内容在挂接收时已经固定，无法保证包含刚收到的 seq。硬件 ACK 只算链路层初步成功，确认表匹配才释放节点缓存。

异常如何处理

  • 没有合法 ACK

    连续失败前两次立即重发；之后指数退避并附加随机抖动。当前为单频点，漫游留待覆盖测试后按需启用。

  • 有 ACK，但确认表没有自己

    最多 8 槽等待确认；超过 3 次交换仍未确认的包重新排队。没有新数据时发 POLL 换取新确认表。

  • PC 断开或来不及读

    网关保留队列；剩余槽少于 2 时暂停挂接收，让节点重试。节点 v1.5 默认 16 槽最多缓冲 560 样本，约 0.175 s（STATUS 占槽后略短），超出后丢最老包并记录 RING_DROP。

  • 网关突然掉电

    已确认但仍在网关 RAM 队列的包可能丢失；当前物理 8 槽，正常反压门限最多积压 7 包，PC 最终记录 RADIO 缺口。确认入队并不等于 PC 已持久化。

PC 如何还原连续样本

  • 唯一键：(node_id, boot_id, seq)

    只保存一份样本，每份副本仍可用于时间配对。重传带来乱序和重复，网关不做去重。

  • oldest_seq 划定永久丢失边界

    oldest_seq 表示节点不再保留旧包；网关队列中仍可能有迟到副本。上位机设计采用 5 s 实时重排窗口，迟到帧仍需记录原始日志，停止采集后应完整重算。

  • 缺口按样本区间，而不是只按包数

    GAP = FIFO 层丢样；RING_DROP = 缓存溢出；RADIO = 已确认的永久缺包。混合故障不能唯一归因时记 AMBIGUOUS；长停顿丢样量未知时记 UNKNOWN_SAMPLE_LOSS，新段独立拟合。

三级时间映射，让样本对齐 UTC

f₁ / 锚点拟合

sample_idx → 节点时间

使用 anchor_idx / anchor_us，按连续段、30 s 窗口拟合实际 ODR。阶段一节点时间单位为 RTC tick，1 tick ≈ 30.52 µs。

f₂ / 收发配对

节点时间 → 网关时间

用 sync_seq_lo + sync_attempt 找到对应副本，配对 sync_txdone_us 与 rx_us；不同网关分别建模。

f₃ / 类 NTP 对时

网关时间 → UTC

PC 每秒发 TIME_REQ，配合 TIME_RESP 的请求/响应时刻；60 s 内选 RTT 最小的 20% 样本拟合。

t_utc_ns = f₃(f₂(f₁(sample_idx)))

u32 序号和时间先展开再拟合；RTC 回绕按 SDK 的 RTC_MAX_COUNT，不把 RTC 当作普通 2³² 微秒。网关微秒约 71.6 分钟回绕。节点采样时钟有 ±1.7% 偏差，不能仅用名义 3200 Hz 生成时间轴。

07 / ON THE FLOOR

在车间，先检查这几件事

上电到采集的检查顺序

  1. 先在台架确认采集

    核对 PA4 与 SPI 接线，读取 CHIP_ID / ERR_REG；静止 Z 轴约 2048 LSB（1 g），INT1 约 91 次/s。安装方向 X 沿运行方向，Z 竖直。

  2. 核对两端 RF 配置

    频点、PHY、access address、CRCInit 一致。先短距离验证接收、ACK 与确认表，再测远距离覆盖。

  3. 验证 PC 收帧和持久化

    CDC 能读到主机帧，CRC 正确，原始日志连续落盘；TIME_REQ / TIME_RESP 往返正常。收帧工具需置 DTR，再按 03 文档检查主机帧。

  4. 上线跑圈，再决定网关布局

    沿线至少跑 10 圈，记录每秒 RSSI、丢包与样本缺口。天线朝外、非金属外壳；喷涂区上机前确认防爆要求。

数据存在哪里，能否离线使用？

主机日志设计为按网关每小时追加写 raw/YYYYMMDD/HH_gw{id}.bin，每条为 u64 pc_recv_ns + u16 len + 主机帧原文，设计为每秒 flush + fsync。处理后按节点每小时写 Parquet，SQLite 记录缺口、状态和时间模型质量。原始日志是重算依据，模式 A 预计约 2 GB / 天 / 节点。

采集链路可运行在车间局域网，不需要公网。PC 绝对 UTC 精度依赖时钟来源，推荐 Linux + chrony 对厂内 NTP。本说明页完全本地运行，保留协议说明与离线解码器；当前固件和测试入口见根目录 README。
