# 01 传感器端固件（公共部分 + 模式 A）

本文描述两种模式共用的部分（BMI323、FIFO、样本编号、发送队列、漫游）和模式 A（全量原始流）。
模式 B（边缘检测、休眠、太阳能）在 05 中描述，复用本文 §1~§3、§5、§6。
当前阶段一只实现单节点、单频点模式 A；漫游与模式 B 为后续设计，范围以 10 为准，实际构建与接板验收见 11，v1.5 远程启停与待机低功耗见 13。

模板：`EVT/EXAM/BLE/RF_PHY`（TMOS + RF_PHY 库），SPI 参考 `EVT/EXAM/SPI/src/Main.c`。
模式 A：主频 `SetSysClock(CLK_SOURCE_PLL_60MHz)`。原设计不开 `HAL_SLEEP`、MCU 常开；现行 v1.5 通过自定义 `app/idle.c` 注册 `HAL_SLEEP` 钩子（不链接厂家深睡眠实现），在采集态调度空闲时进入浅 Idle（`_WFE`），在待机态进入 `LowPower_Sleep`，详见 13。

## 1. SPI 与引脚

| BMI323 | CH592F | 配置 |
|---|---|---|
| CSB | PA12 | GPIO 推挽输出，软件片选，空闲高 |
| SCK | PA13 | 推挽输出 |
| SDI | PA14 (MOSI) | 推挽输出 |
| SDO | PA15 (MISO) | 上拉输入 |

- `SPI0_MasterDefInit()` 默认 4 分频 = 15 MHz，**超过 BMI323 上限 10 MHz**。初始化后必须 `SPI0_CLKCfg(8)`（7.5 MHz）；
  调试阶段可先用 16 分频（3.75 MHz）。显式调用 `SPI0_DataMode(Mode0_HighBitINFront)`（BMI323 支持模式 00/11）。
- 两次访问之间 CS 高电平保持 ≥ 2 µs（手册 tIDLE,rd）。
- 寄存器均为 16 位，低字节在前。
  - 写：`[addr & 0x7F] [data_L] [data_H]`
  - 读：`[addr | 0x80] [dummy] [data_L] [data_H] ...`，第一个读回字节是 dummy，丢弃。
  - FIFO_DATA(0x16) 突发读时地址不自增，连续读即可。
- 上电后 BMI323 默认 I2C，CSB 出现上升沿后 200 µs 切到 SPI。软复位后同样要重新做一次 dummy 读。

## 2. BMI323 初始化序列

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 上电延时 ≥ 2 ms | ΔtPO = 1.5 ms |
| 2 | dummy 读 0x00，延时 ≥ 250 µs | 切换到 SPI |
| 3 | 写 CMD(0x7E) = 0xDEAF，延时 ≥ 2 ms，再 dummy 读 0x00 | 软复位 |
| 4 | 读 CHIP_ID(0x00)，低字节应为 0x43 | 失败重试 3 次，仍失败上报 STATUS 错误码 |
| 5 | 读 ERR_REG(0x01) 应为 0；读 STATUS(0x02) 清 por_detected | |
| 6 | 写 FIFO_CONF(0x36) = 0x0301 | acc_en(b9) + time_en(b8) + stop_on_full(b0)。**必须在使能加速度计之前** |
| 7 | 写 FIFO_CTRL(0x37) = 0x0001 | 清空 FIFO |
| 8 | 写 FIFO_WATERMARK(0x35) = 140；INT_CONF(0x39) = 0x0000；INT_MAP2(0x3B) = 0x1000；IO_INT_CTRL(0x38) = 0x0005 | INT1 已接 PA4：FIFO 水位中断（非锁存、推挽、高有效），详见 10 §3.2 |
| 9 | 写 ACC_CONF(0x20) = 0x70BD | mode=0b111 高性能，avg=0，bw=1(ODR/4)，range=0b011(±16 g)，odr=0xD(3.2 kHz) |
| 10 | 延时 ≥ 5 ms；读回 ACC_CONF 比对；读 ERR_REG 检查 acc_conf_err | |

陀螺仪保持默认关闭。ODR/量程可配置：odr 0xC/0xD/0xE = 1.6/3.2/6.4 kHz，range 0~3 = ±2/4/8/16 g（16 g 时 2.05 LSB/mg）。
以上寄存器值已按 BST-BMI323-DS000-13 的寄存器描述复核；固件初始化时读回 ACC_CONF 并检查 ERR_REG，实板结果仍需接板确认。

配置变更流程（下行命令触发）：封闭当前包 → ACC_CONF mode=0 → FIFO 清空 → 新开 segment → 按新配置重新初始化并使能。

## 3. FIFO 读取与样本编号（核心）

触发方式：BMI323 INT1（PA4）水位中断置 `FIFO_EVT`，另有 20 ms 兜底轮询，见 10 §3.2；每次都把 FIFO 读空。每次：

1. 读 `t_check = sensor_rtc()`（仅用于满 FIFO 停顿超时判定）及 FIFO_FILL_LEVEL(0x15) 低 11 位（单位：字）。帧数 `n = fill / 4`（每帧 4 字），单次最多读 48 帧，多了循环读（最多 3 轮）。
2. fill ≥ 1016 字 → 本次置 `FIFO_FULL` 标志，可能已丢新数据。
   若距上次处理到有效样本已超过 2 s 且 FIFO 满，旧数据可能跨越多次 16 位时间回绕：清 FIFO、重新初始化 IMU、
   新开 segment，下一包置 `GAP|NEW_SEGMENT|FIFO_FULL`。此时不猜测丢样量，sample_idx 只保持已知进度，PC 记录未知损失边界。
3. 突发读 `n × 8` 字节，只读整帧（半帧会被 BMI323 重发，但我们不依赖这个行为）。
4. **FIFO burst 完成后**立即读 `t_read = sensor_rtc()` 和 SENSOR_TIME_0(0x0A) → `st_now`（16 位），保证 `st_now` 不早于本批最新样本（若在读 FIFO 前采样时间参考，期间新增帧会被无符号差误算为早了约 2.56 s，造成假分段和假 8192 样本缺口；自 v1.1 起修复）。
5. 逐帧解析 `x, y, z, t`（int16 小端）：
   - x == 0x7F01：dummy 帧（启动/配置变更后），丢弃，不更新 `last_t`。
   - x、y、z 都是 0x8000：过读，停止解析本批。
   - 连续性判断：`P = 1 << (16 - odr_code)`（6.4 k→4，3.2 k→8，1.6 k→16 个传感器时间 tick，1 tick = 39.0625 µs）；
     `dt = (uint16_t)(t - last_t)`。
     - `dt == P`：正常，`sample_idx++`
     - `dt % P == 0 && dt > P`：丢了 `dt/P - 1` 个样本，`sample_idx += dt/P`，置 GAP 标志并累计丢样数
     - 其他（dt 为 0 或不是 P 的整数倍）：`segment_id++`，置 NEW_SEGMENT 标志
     - 未触发上述满 FIFO 恢复、且相邻样本 RTC 锚点间隔为 2~60 s 时，用 RTC 估计补上 65536 的整数倍；
       间隔 > 60 s 时估计不可靠，直接新开 segment。满 FIFO 长停顿不使用这个估计替代未知丢样量。
   - 任一轴 ≥ 32767 或 ≤ −32767 → 本包置 CLIP 标志。
6. 时间锚点：取本批最新一帧 `(idx_new, t_new)`，
   `age = (uint16_t)(st_now - t_new) * 32 / 25`，`anchor_ts = t_read >= age ? t_read - age : RTC_MAX_COUNT - age + t_read`
   （RTC 计数；1 BMI tick = 1.28 RTC tick）。必须使用无符号 16 位差，避免积压超过 1.28 s 后符号翻转。
   stop_on_full 时最新保留帧也可能是旧数据；锚点误差随积压时间和传感器时钟误差增加，不能统一保证小于 10 µs。
7. 样本写入打包器（见 §5）。

`sample_idx` 为 u32，每次上电从 0 开始，3.2 kHz 下约 15.5 天回绕，由 PC 端展开。

## 4. 时间基准 timebase

节点统一用 RTC（外部 32.768 kHz 晶振，所有板子都有），两种模式相同，包头 `cfg.b7 = 1`。细节见 10 §3.1：
工程预处理宏 `CLK_OSC32K=0`（`HAL/RTC.c` 中该宏非 0 时走内部 LSI）；读 `R32_RTC_CNT_32K` 两次一致；回绕模数为 SDK 的 `RTC_MAX_COUNT = 0xA8C00000`，不是 2³²，PC 端按此展开。
中断回调里直接读 RTC 计数即可，开销很小。

网关常开，用 SysTick 微秒：

- 保留 `CH59x_BLEInit()` 的 SysTick 初始化：最大 64 位比较值、HCLK 60 MHz，并在 PFIC 禁用 SysTick 中断，不另写 CTLR 改动库的前提。
- `gateway_now_us()` 高-低-高读取计数，高字变化则重读；以 32 位整数分解实现除以 60，避免在 RF 活动期间调用 Flash 中的 64 位除法库。
- RF 回调直接取得 u32 微秒，约 71.6 分钟回绕，由 PC 展开；读取、换算及回调均位于 RAM。
- 接板需确认 RF 收发期间计数单调及固定收发延迟；宿主整数换算测试不能替代该项实测。

## 5. 打包器与发送环形缓存

- 当前 `packet_slot_t` 为 252 B：最多 246 B 负载，加交换计数、长度、状态、尝试次数及对齐；v1.5 默认通过 Makefile 编译为 **16 槽**（`SENSOR_RING_SLOTS=16`，链接器另保留 2 KiB 栈）。
  35 样本/包时最多缓存 560 样本，3.2 kHz 下约 0.175 s；STATUS 同占槽，实际略短。原 40 槽为未计入完整 RAM 射频代码的设计估值，v1.4 曾用 22 槽（0.2406 s），v1.5 因链接 `LowPower_Sleep` 搬移 RAM 代码调整为 16 槽（见 13 §4.4）。
- 打包器持有"当前包"，满 35 个样本或遇到以下情况立即封包：GAP、NEW_SEGMENT、配置变更、包内最老样本已等待 100 ms（低 ODR 时限制延迟）。
- 一个包内样本 `sample_idx` 必须严格连续。
- 封包时分配 `seq = next_seq++`（u32），推入环形缓存。缓存满时丢弃**最老**的包（tail，不管处于什么状态），
  累计 `ring_drop_pkts / ring_drop_samples`，下一包置 RING_DROP 标志。
- 每个槽有状态：`QUEUED`（待发或需重发）→ `WAIT_CONF`（已收到硬件 ACK，等确认表）→ 释放。
  **只有在网关 ACK 的确认表里看到自己的 (node_id, seq) 才释放**，原因见 02 §5。
- 发送时先把槽拷贝到独立的 `tx_buf`（248 B）再填每次尝试变化的字段并调用 `RF_Tx`，
  这样 RF 硬件读取期间环形缓存可以安全地被覆盖或丢弃。
- 每个包头带 `oldest_seq` = 缓存中最小的 seq。更早的包不再由节点重传，但仍可能滞留在网关或主机链路；
  PC 不据此立即封死迟到数据，实时等待 5 s，停止后从 raw 完整重算到 final。

## 6. 发送状态机（TMOS 事件 TX_EVT，两种模式共用）

```
TX_EVT:
  选包：最老的 QUEUED 槽；没有 QUEUED 但有 WAIT_CONF 超时的槽 → 发 POLL 包（只有包头，用来换一个新 ACK）
  没有可发的 → 空闲，返回
  拷贝 → tx_buf；填 attempt、oldest_seq、sync_*、cmd_ack
  RF_Shut(); RF_Tx(tx_buf, len, 0xFF, 0xFF)
  在 __HIGH_CODE 等待函数里等结果标志（超时 5 ms，同例程 RF_Wait_Tx_End）
  收到合法 ACK（TX_MODE_RX_DATA、crc==0、类型和长度正确）:
      本槽 → WAIT_CONF，记下 exch_cnt
      按 ACK 确认表释放 node_id 等于自己、seq 低 16 位匹配的槽
      WAIT_CONF 超过 3 次交换仍未确认的槽 → 改回 QUEUED（会产生重复，PC 去重）
      本次为 DATA 时记录 sync_seq_lo/sync_attempt/sync_txdone；POLL/STATUS 不更新配对；处理本节点下行命令
      连续失败计数清零；还有数据 → tmos_set_event(TX_EVT)
  没有合法 ACK:
      attempt++，tx_retry++，连续失败计数 k++
      k ≤ 2 → 立即重发
      k == 3 → 完整设计进入漫游（§6.1）；当前单频点阶段一继续退避
      其余 → 退避 tmos_start_task(TX_EVT, b)，b = min(2^k, 32) tick，加 0~3 tick 随机抖动
新包入队 → radio_request_tx()；发送空闲才置 TX_EVT，已有定时器则等原截止点
```

- 同一时间处于 WAIT_CONF 的槽最多 8 个（等于确认表深度），满了就发 POLL。
- RF 回调 `RF_2G4StatusCallBack` 在中断中执行：只记录状态、crc、抓时间、拷贝 ACK 负载（≤ 40 B），不调用任何 RF API。
- `TX_MODE_TX_FINISH` 回调时抓时间作为 `txdone`。例程在 AUTO 模式下未处理该状态，**codex 需先实测 AUTO 模式下是否会回调 TX_FINISH**；
  若不会，退化为在调用 `RF_Tx` 前抓时间，PC 端多拟合一个常数偏移即可。
- 一次交换最长约 2.5 ms，加上重发，单次 TX_EVT 阻塞 ≤ 5 ms；FIFO 约每 11 ms 触发一次水位中断，容量 80 ms，余量足够。

### 6.1 漫游（切换网关频点）

- 配置里有频点表 `ch_list[]`（模式 B 用 E1/E2/E3，模式 A 用 S1/S2），当前频点 `cur_ch`。
- 进入漫游：依次在其他频点各发 1 个 POLL，第一个回合法 ACK 的频点成为 `cur_ch`；切换频点前先 `RF_Shut`，
  再用 `RF_SetFrequency()`（需 `LLE_MODE_EX_CHANNEL`）或重新 `RF_Config`，codex 实测哪种可靠。
- 所有频点都失败 → 无覆盖状态：数据继续进 RAM 缓存（满了按 §5 丢最老的并记录），扫描间隔模式 A 50 ms，模式 B 从 1 s 起翻倍，最长 8 s。
- 主动切换（第二步再做）：ACK 平均 RSSI 低于 −85 dBm 持续 5 s，用 POLL 探测其他频点，强 6 dB 以上就切换。
- 切换后旧网关上未确认的槽会在新网关上重发，PC 去重。

## 7. STATUS 包与下行命令

- `STATUS_EVT` 每 1 s 生成一个 STATUS 包，和数据包走同一个环形缓存、同一 seq 序列（内容见 02）。
- ACK 中 `cmd_node_id == 本节点 且 cmd_id != last_cmd_id` 时执行命令，记 `last_cmd_id`，在后续每个 DATA/SUMMARY/EVENT 包头 `cmd_ack` 字段回显，命令需幂等。

## 8. 配置存储与 boot_id

- DataFlash（`EEPROM_READ/ERASE/WRITE`，页 256 B）：偏移 0x0000 存配置（node_id、carrier_id、side(L/R)、工作模式、频点表 E/S、
  全网 access address、CRCInit、PHY、发射功率、ODR、量程、带宽、CRC16），
  当前阶段一只保存已实现的节点及采集/RF 配置；0x0100、0x0200 两页以 CRC 保护的追加记录保存 boot 计数，交替擦页时保留另一页的有效记录。`BLE_SNV=0`。
- 每次上电 boot 计数 +1，低 16 位作为 `boot_id`；写入校验失败时停止启动，不复用会话。
- 出厂配置通过 UART1（PA9 TX / PA8 RX，115200）文本命令写入，如 `SET NODE 1`、`SET FREQ 2450000`、`SAVE`。
- 开启硬件看门狗；BMI323 连续 5 次 CHIP_ID 读错或 1 s 内无新样本 → 重新初始化 BMI323 并新开 segment。
